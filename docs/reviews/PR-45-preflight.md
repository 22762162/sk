# PR45 六爻/梅花前置审核（Codex，静态预检）

基于分支 feat/p15-liuyao-meihua；只读主实现与规格，未读取独立参考代码。尚未批准合并/发布。

## 接线前必须解决

1. **L1确定性边界**：liuyao.py 同时 import secrets 并包含 system_cast()。根据 INV-01，
   随机起卦应放在运行态适配层，确定性引擎只接受完整输入；不能用模块名“确定性”代替隔离。
2. **输入验证不足**：lines 接受6.0等浮点（与int相等），day_ganzhi/month_branch没有显式合法域检查；
   梅花接受True并对非整数出现非受控异常。需严格整数类型（拒bool），六十甲子合法组合及月/时支白名单。
   App适配层另外限制报数范围并锁定起卦时间/算法/子时口径，避免自行编造月建日辰。
3. **规则/解读分层**：梅花 relation 同时包含生克事实与“吉/凶/可成”解释。建议将确定性关系码
   与流派解释分离，不能把带倾向的文案当事实Oracle；若维持现规格应在结果中清楚标为传统规则解释。
4. **输出与验收不足**：现有自检只覆盖少量装卦输入。需覆盖4096组爻值、六十日干支、错误输入、
   重放一致性；独立差分只比共享规格定义字段。一致不证明预测准确，差异不能由实现者单方裁决。
5. **模型接线不可省略治理**：当前提示词以八字判断为主；六爻/梅花的独立判断、综合判断、应期及
   可验证事件需 Fable5 单独起草候选，经Codex对称性/偏袒审核与Change Eval再由本人签署。
   不将临时开发指令直接写入运行态，也不把三术混成一个无法分辨贡献的准确率。

P2的公司事实接入不包含PR45，以上需要后续独立PR与对拍证据。
