# PR #43 风险分诊：四模型八字盲测协议

本报告是实现者侧风险分诊，不构成独立异厂商评审。本 PR 只冻结参赛型号、题型配额、统一作答
协议，并为评测用途恢复 OpenAI 网关适配；不加入评分器、不修改生产三方路由，也不产生“谁最准”
结论。变更触及 `consult-engine/gateway.py` 与 `evals/`，按高风险路径处理。

## BLOCKER

无已知代码阻断项。四家连通性测试只发送“返回 OK”的合成内容，密钥值没有读取、回显或写入仓库。

## WARN

1. 60 道基础题的自动答案将来自当前 `consult-engine/luck.py` 规则契约。该模块的大运和地支关系仍
   有待独立对拍，因此自动分数只能称为“当前规则契约一致性”，不得写成命理真伪或真实预测准确率。
2. `gemini-3.1-pro-preview` 是预览型号，供应商可能调整行为、配额或下线。正式复测必须记录实际返回
   的 modelVersion；型号变化后开启新评测世代。
3. 四家调用价格、推理预算、默认采样和限流并不相同。协议统一题目与输出格式，但不能消除产品层级
   和计算预算差异，结果必须连同具体型号、延迟、token 用量一起报告。
4. 三轮完整基础评测预计 48 次 API 调用。运行器必须支持逐批落盘和断点续跑，单一供应商失败不得
   被静默记为答错，也不得用其他型号替补。
5. 真实问事命中率当前没有足够的事前封存、已到期案例。少于 30 条只展示案例不排名，达到 100 条
   才能给阶段性排名；语气自信、篇幅和事后圆说均不是命中证据。
6. 本 PR 未修改 `prompts/`、评测指标计算代码或线上模型路由。评分器将放在后续叠加 PR，避免同一
   PR 同时改作答协议与判分逻辑，遵守 INV-12。
7. 本 PR 叠加在 PR #42 上；PR #42 关于曾在聊天暴露的 Gemini 密钥、供应商数据政策和预算上限的
   风险继续有效，不因本评测协议而解除。
