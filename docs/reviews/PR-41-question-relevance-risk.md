# PR #41 风险分诊：App 原问题直答与经营任务指标

本报告是实现者侧风险分诊，不构成独立异厂商评审。变更涉及 `backend/`、`web/` 与治理
attestation，属于高风险路径；合入前仍须异厂商 reviewer attestation 与本人完整审阅签署。

## BLOCKER

无已知代码阻断项。开发与测试只使用合成问题、合成金额和合成命盘；未把本人问事内容或记录写入
测试、文档、日志或仓库。

## WARN

1. 每次 App 问事在原 D3J 会诊后新增三家并发直答和一次轮换盲评，最多增加四次模型调用，延迟与
   费用都会上升。前端等待上限由 8 分钟延至 12 分钟。
2. 经营指标解析只接受问题中明确出现的当前金额、目标金额和剩余天数，金额目前支持“万/亿”。
   缺字段时不猜测、不展示算术卡，三方仍须直接回答原问题。
3. 相关性闸门是保守启发式检查：任务问题须出现原主题和直接判断词，关系/健康等非任务问题只检查
   主题对应。可能拒绝一条实际相关但措辞过于隐晦的答案；拒绝优于保存答非所问结果。
4. 十神/生克检查只拦截文本中可明确识别的“五行—十神”错配和显式生克说反，不等于完整命理
   正确性证明。无法结构化解析的推理仍须由本人和独立评审判断。
5. 旧预测快照保持不可变，前端只把缺少 `direct_question` 证据的 D3J 记录标为不可行动；不会覆盖
   或删除旧内容。本人刚才指出的旧记录因此仍可审计，但不再在 UI 中冒充有效答案。
6. 本 PR 复用 Claude/Fable 已批准的 `prompts/base/presenter/chat.md` 与既有 judge 提示词；没有编写
   或修改 `prompts/`，避免破坏 INV-10 的提示词起草/审计隔离。

## NOTE

- 新算法版本：`app-forecast-compose-v1.4.0`。
- 新快照字段：`computed_metrics`；`three_role_protocol.direct_question=true` 才按新版完整答案展示。
- 任务指标由 `Decimal` 确定性计算，统一为万元：当前完成率、目标缺口、剩余日均、前期日均及所需
  增幅。AI 只能判断条件与倾向，不能改写这些数字。
- 基础会诊中的错误十神观察不会进入直答上下文；直答自身若出现可识别错误，整次问事停止保存。
- Service Worker 壳缓存升级至 v7，并改为联网优先、离线回退；私密 API 仍不进入 Cache Storage。
