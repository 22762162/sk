## 阻断项

1. **裁判避嫌在当前集合中不可实现**（RFC-0005 §2）。
   三家全参与产出，裁判又在三家中轮换、收到三家全部答案，并要求不裁自家。
   必须明确可实现的排除自身输入/输出矩阵，或另经批准引入未参与作答的第四方。
   匿名化只隐藏标签，不等于排除自身；须覆盖弃答、缺席、映射回填和失败。
   当前RFC只是字段要点，完整schema及新质证/judge提示词尚缺，不能接线。
   最小变更也可回归已批准DESIGN §2.1：三家轮换、全新无状态匿名盲评，明确不是
   独立第四真值源、不保证单场独立性，删除“不得裁自家”的不实保证并允许unresolved。
   本审计不要求默认增加三裁判或第四供应商；真正排除自身是另一需批准的设计。
2. **“今天”没有可信时间锚点**（三个候选硬性边界）。
   当前发送内容含期限但不含冻结as_of/timezone；模型无法知道编排器验收的起点。
   跨日分片评测尤其会漂移。由编排器注入明确冻结点，三个阶段引用同一值，
   不能靠模型当前日期或历史记忆猜测。
3. **不受信内容的指令边界不全**。
   文案只说明facts中的指令不可执行，未完整覆盖问题、材料及封存模型段落中的指令。
   combined“已封存并通过校验”只证明内容完整性/结构，不代表文本可作上级指令。
   明确这些来源均为数据；角色、格式、工具权限不能被其重定义。补合成注入测试。
4. **评测资产归属不能替代拆分**（RFC-0005 §3）。
   facts-only提示词本身回答问题，是对照臂的模型提示词，不是给候选打分的评测器。
   即使分类为评测器提示词，也受INV-12“评测器提示词与指标计算不同PR”约束。
   应分拆独立资产PR并审计，冻结旧基线模型的回溯验证不能由新增对照臂自动替代。

  按钉版规则对齐提示与执行器，不能向三家提供不同于真实验收标准的说明。

  依据问题相关性和可验证条件的取舍规范。相合不构成经验准确率证据。
- 所有示例中的“点명”混字应更正；dissent_note可选与前文“少一字段作废”须澄清。

  装作看不见，也不能将事实推断算作纯术数增益。已有含共同事实标记应贯穿复盘。
