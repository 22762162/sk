# PR #44 风险分诊：四模型盲测评分器与首轮结果

本报告是实现者侧风险分诊，不构成独立异厂商评审。本 PR 在已冻结的 PR #43 协议之上加入确定性
题库生成、同题重排、API 调用、断点续跑和评分代码；没有修改 `request-system.txt`、`config.json`
或生产三方路由，符合 INV-12 的提示协议与评分器分离要求。

## BLOCKER

无已知代码阻断项。首轮运行只使用合成选择题，没有读取或上传真人命盘、用户问事、本机研究记录或
密钥内容。

## WARN

1. 题库答案直接调用当前 `consult-engine/luck.py` 生成，是规则契约回归测试而非独立真值。大运与
   地支关系尚待 `sk-paipan-reference` 独立对拍，结果不得宣传成命理或现实预测准确率。
2. 首轮发现 DeepSeek V4 Pro 在 6,000 completion token 下可能把预算耗在推理而不返回最终 JSON。
   评分器为该 provider 提高到 12,000；缺少最终答案时覆盖率不足 100%，型号自动失去排名资格，
   不再把缺答静默记成知识错误。
3. 对响应的宽松恢复只提取首个 `{` 到末个 `}` 形成的单一 JSON 对象；恢复成功仍记格式不合规。
   这样可以分开知识正确率与协议遵从率，但不能防御任意恶意输出。本评测输入为静态合成题，不接受
   用户内容。
4. 断点文件位于 gitignored `evals/reports/`，逐批原子替换。最终保留记录不累计被重试批次的延迟和
   token，因此汇总报告已单独披露 DeepSeek 7 次补跑，不能把最终 token 合计当成实际总成本。
5. Gemini 3.1 Pro Preview 和其他供应商型号未来可能改变；配置或实际 model release 变化必须开启新
   评测世代，不能与本结果直接拼接。
6. 四选一题容易出现天花板效应。前三家并列满分只能说明本题集区分度不足，不能据此决定生产胜者。
7. 本 PR 叠加 PR #43、#42、#41；所有上游高风险审阅、供应商数据政策、密钥轮换和本人签署要求
   继续有效。

## NOTE

- 题库 60 题：十神 20、地支关系 16、五行计数 8、大运 8、干支历法 8。
- 每家 3 轮、每轮 4 批、每批 15 题；题序与选项位置按固定种子重排。
- 四家最终覆盖率均为 100%，无 API 缺席；ChatGPT、Gemini、DeepSeek 180/180，Claude 179/180。
- 真实问事准确率没有足够的事前封存案例，当前明确不排名。

## 验证

- 新增评分器单元测试 5 项通过：冻结配额、选项唯一性、答案隐藏、确定性重排、严格/宽松 JSON、
  完整度排名门槛与满分汇总。
- 后端单元测试共 22 项通过。
- 48 个计划批次全部完成；DeepSeek 额外补跑 7 次后取得完整最终答案。
- Python 语法检查、`git diff --check`、`governance-check`、`redline` 通过。

结论：实现者侧建议作为实验工具进入评审。对外只能发布“基础规则一致性并列”与工程指标，不得在
真实封存案例达到门槛前宣称任何一家“问事最准”。
