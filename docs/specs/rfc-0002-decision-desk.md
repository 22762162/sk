# RFC-0002：统一决策台 P0/P1

状态：按本人 2026-08-31 确认的整合方案实施；合入仍须独立评审与本人签署。

## 范围与边界

本次只改 App 内部数据与呈现，不修改 lock 钉版 contracts、排盘算法、运行态提示词或评测协议。
五入口为今日、问事、看盘、公司、我的；记录是共用二级视图。专家页暂时保留，旧记录不删除。
P2 大脑连接、P3 起卦引擎和 P4 方法对照是独立后续 PR，不伪装成已经接通。

## 数据约定

- profiles.id 是分析主体的唯一身份，不以相同生日自动合并不同人。active 仅为 UI 默认选择。
- companies 与 company_projects 分别表示公司和业务项目；项目必须隶属一个公司。
- company_memberships 关联公司、可选项目、个人档案、角色、有效日期及使用授权；无授权、过期和
  不属于本次公司/项目的关联不可参与问事。公司成立盘不是必填项，不用默认日期补造。
- profile_events 是本人确认的个人经历，append-only；与历史 AI 研究参考分开存储。
- inquiries 增加 scene/company_id/project_id/scope_json；scope_json 在任务启动前冻结主体版本、
  公司/项目版本、明确选中的关联人员和事件来源。任务不得在异步运行中重新读取已变化的资料。
- 个人事项拒绝公司/项目/关联人字段；公司事项明确选公司、可选项目、主参考人和至多六位已授权
  关联人。所有云端输入用匿名别名替换档案名，不发送原始出生时间和内部记录 ID。
- 个人校准不混入公司问题的复盘。旧预测原文、哈希、锁定时间和复盘不回写。

## 迁移

SQLite v2→v3 只新增表和 inquiries 列；旧事项标记为 personal，原 scope 为空表示历史未记录。
保留所有旧 ID，迁移可重复执行，拒绝打开高于当前版本的数据库。开发和测试仅使用临时合成库，
本次不打开或迁移生产数据库。发布前用 SQLite backup 做一致性备份，再由新版本执行迁移。

## 统一数据流

选择主体和场景 → 展示资料范围并确认 → 校验关联/授权/版本 → 冻结范围与计算资料 → 三家独立
会诊 → 三家原问题直答 → 盲评 → 全部到齐才锁定预测。任何模型缺席不得保存成正式三方结论。
计算事实与旧研究在看盘页直接展现；查看不触发模型调用，也不将历史研究自动认定为事实。

公司资料在本期仅支持用户明确填写的去标识业务背景。大脑连接状态固定为未接入，不能显示虚假
营收或编造数据更新时间。公司营收不是个人收入，不按命盘评价人员任用或信用。

## 验收

1. v2 合成数据库迁移后旧预测哈希和复盘完全不变，重跑迁移不重复。
2. A/B 档案切换后，问事和复盘不混入对方或公司的资料。
3. 跨公司/跨项目、未授权、过期关联、重复人员、过时版本与未确认范围全部拒绝。
4. 异步任务期间修改档案不改变已冻结输入。
5. 原问题直答轮仍收到同一匿名范围资料；三家不齐不保存。
6. 五入口在手机和桌面无横向溢出；资料、事件、研究历史无需离开 App 即可查看。
