# RFC-0004 · 三术三段封存编排协议 v1.1

状态:实现与交叉审核中,未接线。回应 sanshu-inquiry-v1 盲审计的 **B1-B6**/R1-R3 与
codex-rfc0004-feedback 六条(逐项回应见 docs/coordination/claude-rfc0004-response.md);
候选提示词内容不在本 RFC/实现 PR 中(INV-12)。

## 0. 三方×三段调用矩阵与预算(feedback-1/6)

- 一次正式三术问事 = 三家供应商 × (bazi/gua/combined) = **9 次基础调用**;匿名质证与盲评另计,
  整单调用数硬封顶(编排器常量),逐调用超时,失败重试≤1 且不得换供应商,支持整单取消。
- 编排器实现"单供应商三段链";上层三方循环逐家执行,校验每家身份与三段覆盖。
- **正式单要求三家全集(3/3,与 main 现行 backend 闸门一致——用户三方核心要求)**:
  任一家缺席/失败 → 本单不得保存为正式结果(中间态仅可展示,明确标注不完整);
  PR#40 的 ≥2 降级只适用于旧版普通会诊,不适用于本协议。合法 abstain ≠ 缺席:
  某家某段结构化弃答仍算到场,不强迫结论。**统计保留 method=liuyao|meihua 维度**,
  永不合并为单一"卦象命中率";双卦法同题为后续显式模式。

## 1. 封存 = 编排级物理隔离(B1)

**每家供应商各一套**下表三次独立调用(三家共 9 次,见 §0),由 `sanshu_orchestrator` 编排:

| 调用 | 输入(白名单,超出即拒) | 输出 |
|---|---|---|
| bazi | 问题、期限、八字材料(四柱/大运/流月文本)、允许的公共背景 | bazi 段 JSON |
| gua | 问题、期限、受信卦快照(确定性引擎输出+装卦哈希)、允许的公共背景 | gua 段 JSON |
| combined | 问题、期限、**两份已封存并通过校验的段落原文+各自 seal 哈希**、公共背景 | combined 段 JSON |

- 八字材料与卦快照**永不同时出现**在 bazi/gua 调用中;combined 只见封存结果,不见原始材料。
- 每次调用独立 run manifest;编排器另写 sanshu-manifest:三个 run_id、各输入材料哈希、
  两段 seal(canonical-JSON SHA-256)、校验器版本、结果状态。
- `method` 由编排器按受信卦快照回显注入,模型不得自选(R1)。

## 2. 输出契约与 fail-closed 校验器(B2)

- Schema 文件 `consult-engine/schemas/sanshu-sealed-v1.json`(候选期本地钉版;
  接线获批时按 INV-05 走 sk-contracts RFC 发版后改为 lock 引用)。
- `sanshu_validator` 逐字段校验:必填、类型、枚举、`additionalProperties:false`、
  日期窗口正则、事件数组 0–3、置信度枚举与"combined ≤ max(单法)"依赖规则。
- **任一错误 → 整段作废并丢弃本次调用结果**(INV-06 fail-closed),错误进编排器日志与 manifest,
  不落用户可见结论。

## 3. 跨段禁词 = 版本化词表 + 归一化(R2;v1.1 修正)

- 词表版本 `sanshu-banlists-v1`(随校验器代码钉版),**只收各法独有词**:
  - `BAZI_ONLY_TERMS`(禁出现在 gua 段):大运/流年/流月/日主/四柱/各柱名/十神全称/纳音/身强身弱…
  - `GUA_ONLY_TERMS`(禁出现在 bazi 段):六十四卦全名、卦/爻/世应/动变/互卦/体用/卦宫/纳甲/六神全称…
  - **共享词不禁**:干支(卦的月建日辰、旬空依据是合法时间事实)、"用神"(两法皆用)、单字八卦名(误伤日常语)。
- 归一化:NFKC → 去空白与标点 → 拉丁小写;对段落序列化后的**全部嵌套字符串**扫描。
- **公共背景污染检测**(feedback-2):进入编排前对问题/背景扫两法独有词与干支复合词密度
  (≥2 个即判污染);命中→整单拒绝并给出原因,**不默默改题**,原题原文留档。
- 词表只拦显式借词;**真正的隔离由第 1 节物理隔离承担**,词表是第二道防线,不单独作证。

## 4. 缺席/弃答/事件契约(B3/B4)

- 每段统一结构:`{"status":"ok|abstain","reason":...}`;**材料缺席由编排器判定**:
  缺卦→不发起 gua 调用,该段记 `absent`(编排器写入,非模型填写);缺任一法→combined 不启动,
  整单记 `combined_status:"not_run_missing_material"`,复盘登记为"未生成"。
- abstain 为合法一等结果:`status:"abstain"` + 结构化 reason,该段不可评分、不计惩罚——
  消除"必须给日期"的编造压力;给出 yingqi 则必须 `YYYY-MM-DD~YYYY-MM-DD`。
- **三表各自的事件数组**:bazi/gua/combined 每段 `verifiable_events`(0–3),每件含
  `event_id`(编排器补发 UUID)、`statement`(可判真伪陈述)、`window{start,end}`(Asia/Shanghai,闭区间)、
  `metric{indicator,comparator,threshold?,unit?}`、`adjudication`(到期判定标准)。
  复盘三表分列计分;combined 事件不回填单法表。

## 5. 装卦绑定(B5;v1.1 软化并加固)

- gua 调用输入附 `cast_hash`;输出须回显同一哈希;manifest 与快照存档同哈希——
  **哈希只证明"本判词绑定这唯一一次装卦",不证明内容真实、不给幻觉盖戳**(feedback-5)。
- **矛盾拒绝**:校验器持受信卦名集(该快照的本/变/互卦名);gua 段任何字符串出现集合外的
  六十四卦名 → 整段作废("声称另一卦"可机检)。结构字段一律以受信快照为准,模型复述不作数。
- 快照缺字段/内部矛盾/与 method 不符 → 确定性层校验失败,**不发起解读调用**(fail-closed)。

## 5b. 公司事实进入阶段(feedback-3;终稿共识)

**同一份经本人确认的 L1/L2 事实摘要给三段各一份**(基线一致,归因不混杂),整单标注
`含共同事实背景`;每单存 `facts_exposure` 三段标注与 facts_hash。**任何此类样本不得称
"纯术数"**;独立评测须设 facts-only(仅事实无术数)基线臂供消融比较。
L3/L4 不因本编排新增任何通路(入口仍为 PR#47 确认快照)。

**四时间戳区分**(交接终稿):`known_at`(事实**可获知**时点,非事实所属期)/`confirmed_at`(本人确认时点)/
`frozen_at`(本单冻结时点)/`first_call_at`(首次模型调用时点),观察/读取时间独立记录,全部入 manifest;
回看型样本(问过去)单独标注,**不得混入前瞻成绩表**。
污染检测的干支密度阈值(≥2)为**候选启发式**,已知会误伤"两个合法时间条件"类问句(测试留档),
不作隔离证明;豁免与阈值调整留成品验收。

## 5c. 分母披露(feedback-4)

复盘按 bazi 表、每卦法表(liuyao/meihua 分列)、combined 表分别披露:
总样本、可评分数、abstain 率、技术失败率;弃答不计命中分母但必须展示,不得抬高表面准确率。

## 6. 红线(R3)

适用红线条款由**实际发送的 system 正文**携带(不靠头部注释);字段级作废由本校验器执行,
后端字符串遮蔽保留为末道防线。候选提示词 v2 起草时按本 RFC 的输入/输出契约写作。
